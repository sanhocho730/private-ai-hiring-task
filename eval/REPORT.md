## 1. 분류 모델

| 방식 | 정확도 |
|---|---|
| 규칙만 (표식 없으면 O) | 9/9 |
| qwen2.5:3b 단독 | 8/9 |
| **qwen2.5:3b + 규칙 (높은 등급 택함, 채택)** | **9/9** |
| exaone3.5:2.4b 단독 | 7/9 |
| exaone3.5:2.4b + 규칙 | 7/9 |

- qwen2.5:3b는 05 계약 문서를 O로 매긴다(정답 S). 규칙(`법무팀`, `위약금`)이 S로 올려 최종 9/9가 된다.
- exaone3.5:2.4b는 01 핸드북과 02 FAQ를 S로 올려 매긴다. 규칙은 등급을 올리기만 하고 내리지는 않으므로 합쳐도 7/9다. 그래서 분류에는 qwen을 쓴다.
- **규칙만으로도 9/9지만, 규칙 단어를 이 9개 문서를 보고 골랐기 때문에 일반화의 근거는 아니다.** 규칙은 LLM이 낮게 매길 때를 막는 하한선으로만 쓴다.

## 2. 답변 모델

같은 검색·권한 필터에서 답변 모델만 바꿔 12개 질문을 실행했다. 핵심 정보는 `tests/questions.md`의 "기대" 칸에서 가져온 14개 항목이다(예: 7번은 "90일"과 "2027-06").

| 모델 | 답변 문장에 핵심 정보 | 출처 줄 포함 | 한자·가나 섞인 답 | 유출 토큰 | 평균 응답 |
|---|---|---|---|---|---|
| qwen2.5:3b | 11/14 | 14/14 | 1개 (`10월 5日부터`) | 0 | 9.6초 |
| **exaone3.5:2.4b (채택)** | **12/14** | **14/14** | **0개** | **0** | **6.1초** |

- qwen2.5:3b는 7번을 "문서에서 확인할 수 없습니다"라고 답했다. 계약 문서가 프롬프트에 있었는데도 그랬다.
- 두 모델 모두 7번의 "2027-06"과 11번의 "요청"을 답변 문장에서 빠뜨린다. 코드가 붙이는 출처 줄에는 있어서 출력 전체로는 14/14다.
- 유출 토큰은 두 모델 모두 0이다. 초과 문서가 프롬프트에 들어가지 않으므로 모델과 무관하다.
- qwen2.5:7b는 이 기기에서 스왑 때문에 첫 질문도 11분 안에 끝나지 않아 비교에서 뺐다(개발 중 관찰, 이 스크립트로는 재실행하지 않음).

임계값 하나씩만 바꾸고 나머지는 기본값으로 고정했을 때, 12개 판정이 모두 맞는 구간:

| 임계값 | 현재 값 | 12/12 구간 | 경계를 정하는 질문 |
|---|---|---|---|
| `S_HINT_THRESHOLD` | 0.55 | 0.47 ~ 0.59 | 아래: 5번 초과 S 0.468(힌트 없어야 함) / 위: 3번 0.595(힌트) |
| `C_HINT_THRESHOLD` | 0.46 | 0.44 ~ 0.48 | 아래: 6번 초과 C 0.437(힌트 없어야 함) / 위: 9번 0.483(힌트) |
| `RELEVANT_THRESHOLD` | 0.50 | 0.40 ~ 0.59 | 아래: 8번 열람 문장 0.397(거부해야 함) / 위: 9번 열람 문서 0.592 |

- S와 관련도 임계값은 폭이 0.1 이상이고, 현재 값이 구간 안쪽에 있다.
- **C 힌트 구간은 0.44~0.48로 좁다.** 6번(팀장, 매출 질문)과 9번(팀장, 대성식품 물량)의 C 점수 차이가 0.046밖에 안 된다. 새 질문에서 가장 먼저 틀릴 곳이 여기다.
- 4번과 8번은 초과 C 점수(0.481, 0.506)가 9번(0.483)과 비슷하거나 더 높다. C 점수만으로는 가를 수 없어서, "열람 문서 점수가 기준 이상이고 C보다 높을 때"라는 조건을 더했다(DESIGN.md 실패한 시도 ①).
- 이 임계값은 12개 질문으로 정하고 같은 12개로 확인한 값이라, 따로 떼어 둔 검증 질문은 없다. 문서와 질문이 늘면 질문을 나눠 검증해야 한다.
